# Actinic Keratosis vs Seborrheic Keratosis Classifier

A Convolutional Neural Network built with TensorFlow/Keras that classifies dermoscopic skin lesion images as **Actinic Keratosis** or **Seborrheic Keratosis**, with a Streamlit web app for interactive inference.

> **Data integrity notice:** The source dataset ships as 9 flat class folders (no pre-made `train/`/`validation`/`test` split). This project uses only 2 of the 9 classes and builds its own **stratified 70/15/15 split from raw files** (see notebook, split-construction step) — there is no risk of the augmented-duplicate leakage that pre-split datasets can have, because the split is generated fresh from disjoint filenames. **Note the source folder is misspelled `Acitinic Keratosis` on Kaggle** — the notebook's folder-matching logic accounts for this; don't assume the display name matches the class label everywhere.

## Dataset

- **Source:** [Multiple Skin Disease Detection and Classification](https://www.kaggle.com/datasets/pritpal2873/multiple-skin-disease-detection-and-classification) (Kaggle, ISIC-derived)
- **Classes used:** `Actinic Keratosis`, `Seborrheic Keratosis` (2 of 9 available classes in the source dataset)
- **Structure:** custom-built `train/`, `validation/`, `test/` folders, each with `Actinic Keratosis/` and `Seborrheic Keratosis/` subfolders, generated by the notebook's split step — not shipped pre-split by the source
- **Split sizes (this run):** 700 train / 150 validation / 150 test, test set balanced 75/75
- **Note:** unlike the apple dataset this project replaced, these images are *not* pre-augmented duplicates — each file is a distinct clinical/dermoscopic photo. Class imbalance in the raw source folders was handled with `class_weight` during training rather than by duplicating minority-class images.

## Model

Two architectures were compared:

1. **Custom CNN** — trained from scratch. 3 convolutional blocks (Conv2D → BatchNorm → Conv2D → BatchNorm → MaxPool → Dropout), `GlobalAveragePooling2D`, dense head, single sigmoid output. **Overfit badly** on this dataset size — validation accuracy stayed near 0.50 (chance level) with diverging train/val loss. Kept in the notebook as a documented baseline, not used for deployment.
2. **Transfer learning (EfficientNetB0)** — ImageNet-pretrained backbone, frozen, with a `GlobalAveragePooling2D` → `Dropout(0.4)` → `Dense(1, sigmoid)` head. This is the model used in the deployed app.

| Setting | Value |
|---|---|
| Input size | 224 × 224 × 3 |
| Batch size | 32 |
| Loss | Binary cross-entropy |
| Output | Single sigmoid neuron (0 = Actinic Keratosis, 1 = Seborrheic Keratosis) |
| Optimizer | Adam |
| Class weighting | `balanced`, applied during `.fit()` to offset raw class imbalance |

## Results

| Model | Val Accuracy | Test Accuracy | Precision | Recall | F1 |
|---|---|---|---|---|---|
| Custom CNN (from scratch) | ~0.50 | not evaluated — discarded, chance-level | — | — | — |
| EfficientNetB0 (transfer) | 0.8133 | 0.8067 | 0.8277 (macro) | 0.8067 (macro) | 0.8035 (macro) |

**Per-class breakdown (EfficientNetB0, test set, n=150):**

| Class | Precision | Recall | F1 | Support |
|---|---|---|---|---|
| Actinic Keratosis | 0.9107 | 0.6800 | 0.7786 | 75 |
| Seborrheic Keratosis | 0.7447 | 0.9333 | 0.8284 | 75 |

**Known limitation:** recall on Actinic Keratosis (0.68) is notably lower than on Seborrheic Keratosis (0.93) — the model under-detects the clinically higher-stakes, precancerous class more often than the reverse. This asymmetry is not resolved in the current model; see the "Next Steps" note in the notebook for the planned fine-tuning fix (unfreezing top EfficientNet layers) before treating this as production-ready.

## Disclaimer

This model is a course project artifact trained on a small academic dataset. It has not been clinically validated, distinguishes only two lesion types out of the many that exist, and should not be used to make, delay, or avoid any medical decision. The deployed app surfaces this disclaimer directly to end users.

## Setup

```bash
git clone <your-repo-url>
cd <your-repo>
pip install -r requirements.txt
```

Place your trained model at `models/efficientnet_transfer_best.keras` (not included in this repo by default — see note in `.gitignore` considerations below).

## Running the App

```bash
streamlit run app.py
```

Then open the local URL Streamlit prints (typically `http://localhost:8501`), upload a lesion image, and view the prediction with confidence score.

## Deployment

1. Push `app.py`, `requirements.txt`, and `models/efficientnet_transfer_best.keras` to a GitHub repo.
   - Check model file size first: `ls -lh models/efficientnet_transfer_best.keras`. EfficientNetB0's frozen weights alone are ~15 MB plus your trained head — if it's over ~100 MB, GitHub will reject a plain push — use [Git LFS](https://git-lfs.com/) instead.
2. Deploy via [Streamlit Community Cloud](https://streamlit.io/cloud) (or any host that runs `streamlit run app.py`), pointing at `app.py`.
